# 方向 A Prompt 优化负结果：7B 模型无法区分"直接父"与"相关"

> 日期：2026-11-25
> 结论：**4 种 prompt 变体均无法提升 LLM 先验精度；精度瓶颈是 7B 模型的领域知识上限，不是提问方式。但也由此把方法定位澄清为「面向 MB 的因果特征选择」**

## 一、背景

A2/全小客户端实验显示：LLM 先验召回好（能找到真父节点），但精度低（把祖节点/子节点/相关节点也标成"相关"）。本轮尝试通过 prompt 工程提升精度。

## 二、4 种 prompt 对比（目标 HypoxiaInO2，真父 = CardiacMixing + LungParench）

| 变体 | 格式 | 父召回 | 父精度 | 说明 |
|---|---|---|---|---|
| 逐特征二元（原版）| 19 次查询 | 1.00 | 0.17 | 召回最好 |
| 列表式·直接父 | 1 次查询 | 0.00 | 0.00 | 完全跑偏（返回 BirthAsphyxia/DuctFlow/LVH/LungFlow）|
| 列表式·对比分类 | 1 次查询 | 0.50 | 0.50 | 只对一半 |
| 逐特征四分类 | 7 次查询 | — | 2/7 对 | 几乎全判成 "direct parent" |

## 三、结论

prompt 工程无法让 `deepseek-r1:7b` 区分"直接父节点 / 祖先 / 子节点 / 相关节点"。它对 CHILD 这种技术性医学网络的因果结构本身了解不足，只能给出"相关性"判断。这是**模型能力上限**，不是提问方式问题。

## 四、由此澄清的方法定位

方法应定位为**面向 MB（马尔可夫毯）的因果特征选择**，而非"纯父节点发现"：

- **MB = 相关集合**（父 + 子 + 配偶），LLM 的"宽相关"先验天然对齐 MB——这解释了全小客户端实验中 LLM 先验的 MB 召回反而高于"完美父先验"（它歪打正着标中了配偶 HypDistrib）；
- **CI 负责最小性**：拒掉距离远的祖节点（Disease、LVH），保证最小相关集；
- **先验负责召回**：救回 CI 因低功效漏掉的弱 MB 成员。

## 五、论文的诚实表述

> 语义先验提供的是"相关性"信号，天然契合 MB 任务；它提升 MB 召回，但"直接父节点"级的精度受限于模型能力，需由数据侧（CI + 定向规则）保证。
